This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## About This Repository

This is the **EcoCommons Australia** notebooks repository — a collection of ecological modelling and geospatial tutorials. Each notebook exists in two formats:
- `.ipynb` — Jupyter notebook (runnable in Google Colab or ARDC Jupyter)
- `.qmd` — Quarto Markdown (runnable in RStudio)

Notebooks are organized into three categories (the `readme_section` column in the CSV — `models`, `skills`, `computer_vision`):
- **Ecological Modelling** (`models`) — GLM, Random Forest, Occupancy Models, EOO/AOO
- **Geo/Ecological Skills** (`skills`) — raster format conversions, species data retrieval, imbalanced datasets, richness/diversity
- **Computer Vision** (`computer_vision`) — camera-trap / image-based workflows (e.g. SpeciesNet)

## Updating the README Notebook Table

**Do not edit the notebook table in `README.md` manually.** It is auto-generated.

To add a new notebook:
1. Place both the `.ipynb` and `.qmd` files in `notebooks/`
2. Add a row to `automation/notebooks-table-data.csv` (9 comma-separated fields: `display_name, notebook_name, econotebook_blogpost_path, youtube_video_path, github_repository_path, arxiv_index, should_open_in_sagemaker_labs, readme_section, doi`)
   - `readme_section` must be one of `models`, `skills`, or `computer_vision`
   - `doi` is the bare Zenodo DOI (e.g. `10.5281/zenodo.19551976`); leave empty if none. Fields must not contain commas (the CSV is split naively on `,`).
3. Regenerate the table:
   ```bash
   python3 automation/autogenerate_notebooks_table.py
   ```
4. Commit to a feature branch and open a PR.

**Generator notes** (`automation/autogenerate_notebooks_table.py`):
- Section order and headers are defined by `READMESection` (enum) + the `*_SECTION_HEADER` constants; the render order is Ecological Modelling → Computer Vision → Geo/ecological skills.
- The table is injected between **two** `<!--- AUTOGENERATED-NOTEBOOKS-TABLE -->` tokens in `README.md`. Both must be present or the script errors — if regeneration fails, check that the opening token still exists above the tables.

## Converting QMD to IPYNB

**R notebooks:** the script `notebooks/Convert_QMDtoipynb.R` converts a `.qmd` to `.ipynb` using R's `jsonlite`. Edit the `qmd_file`/`ipynb_file` paths at the top before running. It only recognizes ` ```{r} ` fences as code cells — everything else (including ` ```{python} ` fences) becomes a markdown cell, so **do not use it for Python notebooks.**

**Python notebooks:** use `quarto convert file.qmd`, which converts qmd↔ipynb natively and preserves cell structure and chunk options. If the qmd's `jupyter:` kernel isn't registered where quarto looks, activate that env first (e.g. `source ~/eco_env/bin/activate` then `QUARTO_PYTHON="$(which python)" quarto convert ...`).

### Portable kernels for published notebooks

Published `.ipynb`/`.qmd` must run on machines that don't have local kernels like `eco_env`. Before shipping:
- Set the ipynb `metadata.kernelspec` to the generic `{ "name": "python3", "language": "python", "display_name": "Python 3" }` (Colab ignores it anyway).
- Set the qmd YAML header to `jupyter: python3`.
- Remove any leftover Quarto YAML front matter (`--- / jupyter: … / ---`) that `quarto convert` leaves at the top of the first markdown cell.
- List every imported package in the install cell (e.g. `matplotlib`) so it works on a bare environment, not just one with pre-installed libs.

### Editing existing `.ipynb` programmatically — preserve formatting

`.ipynb` files in this repo use **inconsistent** JSON formatting (varying indent, some `ensure_ascii=False`, Colab metadata). Rewriting a whole notebook with `json.dump(..., indent=N)` reformats every line and produces a massive, unreviewable diff. To make a small content change, **splice the text surgically** instead: locate the target line inside the `source` array, insert the new JSON-encoded string element(s) with the same leading indentation, and leave the rest of the bytes untouched. Validate with `json.loads` before writing. This keeps diffs to just the changed lines.

## Per-notebook sections

Each notebook carries two standard sections:
- **"Other file formats of this notebook"** — a table linking the notebook's other format (`.ipynb`/`.qmd`) + Colab/ARDC + DOI badge. Placed near the **top**: directly after the "Script … info(rmation)" section and immediately **above** the following heading (usually `Introduction`; some notebooks have no Script heading, in which case it goes just above `Introduction`).
- **"How to cite this Notebook"** — a citation, placed at the **bottom**, just before the `# How to Cite EcoCommons` block (or before `## References` for notebooks without that block).

Citation metadata (authors, title, year, version) is pulled from the notebook's Zenodo record via the DOI: `https://zenodo.org/api/records/<id>` where `<id>` is the number after `zenodo.` in the DOI. Include `(Version X)` only when the record has a `version`. Heading wording/levels vary between notebooks (some use bold `# **Introduction**`), so match anchors tolerantly.

**Data flow:** This repo holds the executable source files (`.ipynb` / `.qmd`). The notebook-blog consumes those `.qmd` files and publishes them as the browsable documentation site. The README table in this repo links back to the rendered pages on notebook-blog via auto-generated badges.
